# Technical Report: Passive Network Telemetry Pipeline

**Module:** `src/01_passive_network`
**Objective:** Architecture documentation for the ingestion, standardization, and quality control of unidirectional network sensor logs prior to feature extraction.

## Pipeline Overview
The `01_passive_network` directory serves as the ingestion layer for the threat detection pipeline. It is strictly designed to handle metadata generated by passive network sensors, ensuring absolute compliance with the SIH 26145 constraint prohibiting payload decryption. The module normalizes fragmented, multi-format sensor logs into a single, unified data stream for downstream machine learning evaluation.

## Component Breakdown

### 1. Sensor Normalization
Network sensors output data in differing formats. These scripts ensure that regardless of the sensor used, the resulting data structure is identical.
* **`normalize_zeek.py`**: Parses raw protocol metadata logs generated by Zeek (including `conn.log`, `dns.log`, and `ssl.log`). It extracts critical connection states and protocol metadata, converting the raw text output into a standardized tabular format.
* **`normalize_suricata.py`**: Ingests Suricata's `eve.json` log files. It maps specific flow and protocol events into the exact same standardized schema as the Zeek script, ensuring the AI model receives uniform data regardless of the active sensor deployed on the network.

### 2. Telemetry Orchestration
Raw network monitoring tools often fragment data across multiple specialized files.
* **`merge_telemetry.py`**: Operates as a correlation engine. It uses unique connection identifiers (UIDs) and timestamps to stitch fragmented logs (e.g., base connection statistics logged separately from their associated DNS queries) into single, comprehensive flow records.

### 3. Quality Assurance and Validation
To maintain pipeline stability and guarantee strict adherence to problem statement constraints, automated quality control gates are enforced before data is passed to the feature engineering layer.
* **`validate_telemetry.py`**: Serves as the strict quality control mechanism. It scans the merged telemetry to enforce schema compliance, drops malformed or incomplete rows, verifies that critical routing headers (like IPs and Ports) exist, and confirms that no raw payload data has inadvertently entered the pipeline.
* **`benchmark_performance.py`**: A dedicated stress-testing module. It processes dense sample datasets through the ingestion pipeline to measure processing latency and throughput (flows per second), providing mathematical proof that the architecture can sustain real-time, line-rate traffic speeds.
