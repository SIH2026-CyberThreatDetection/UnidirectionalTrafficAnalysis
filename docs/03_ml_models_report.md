# Technical Report: Machine Learning & Threat Detection Pipeline

**Module:** `src/03_ml_models`  
**Objective:** Architecture documentation for the dual-engine artificial intelligence pipeline responsible for classifying network flows into the 6 SIH threat categories and outputting JSON telemetry for the SOC dashboard.

## Pipeline Overview
The `03_ml_models` directory contains the mathematical core of the threat detection system. It ingests the passive 12-Feature Golden Schema generated by the `02_feature_dataset` pipeline and applies a dual-engine machine learning approach—combining supervised multiclass classification with unsupervised anomaly detection—to identify both known attack signatures and zero-day deviations.

## Component Breakdown

### 1. The Dual-Engine Core
These modules define and train the primary threat detection algorithms.
* **`train_xgboost.py` & `classifier.py`**: The supervised learning engine. These scripts configure, train, and serialize the XGBoost multiclass model. They map the dataset to the 6 specific SIH 26145 attack categories (DDoS, Botnet C2, DNS Tunneling, Encrypted Malware, Reconnaissance, Data Exfiltration).
* **`anomaly_detector.py`**: The unsupervised safety net. This script trains an Isolation Forest model to act as a mathematical metal detector, specifically targeting asymmetric flows and unseen volumetric spikes (Zero-Days) that evade the supervised XGBoost model.
* **`train.py`**: The orchestrator script for the training phase, allowing both engines to be compiled and serialized into the `/models` directory simultaneously.

### 2. Data Preparation & Integrity
Before the AI can make predictions, the incoming matrices must be rigorously formatted.
* **`data_loader.py`**: A utility module that handles the ingestion of the master CSV files from the M2 pipeline, ensuring memory-efficient loading of massive network datasets.
* **`preprocessing.py`**: Handles final mathematical scaling and encoding (if required) before the data is fed into the models, ensuring optimal algorithmic convergence.
* **`schema_validator.py`**: The final safety checkpoint. It verifies that incoming live streams or test datasets strictly match the required 12-feature structure, preventing the inference engine from crashing when confronted with missing or malformed columns.

### 3. Inference & SOC Integration
This is the live execution layer that bridges the AI to the M4 Detection Intelligence dashboard.
* **`predict.py`**: The inference terminal. It loads the pre-trained `.pkl` models and applies the dual-engine fallback logic (overriding `benign` XGBoost predictions with `zero_day_anomaly` if the Isolation Forest triggers). Crucially, it translates the mathematical outputs (`predict_proba`) into a strict, machine-readable JSON contract containing `timestamp`, `flow_id`, `threat_class`, and `confidence` percentages.

### 4. Evaluation & Explainability
These scripts are designed to provide absolute transparency to the hackathon judges, proving the AI is not a black box.
* **`evaluate_xgboost.py` & `evaluate.py`**: Automated scoring modules that test the trained models against unseen chronological datasets, generating standard classification metrics like accuracy, precision, recall, and F1-scores.
* **`explain_model.py`**: The visual proof generator. It creates the Confusion Matrix (showing exact prediction successes and failures) and the Global Feature Importance charts, mathematically proving to evaluators that the AI utilizes engineered metadata (like `dns_query_length`) to detect threats without payload decryption.
